# Detection 04 – Investigation of High Severity File Creation Alert

## Executive Summary

During the execution of Detection 03, Wazuh generated a high-severity alert (Rule 92213) indicating that an executable created a file inside a directory commonly abused by malware.

The investigation determined that the alert was a **false positive** generated by PowerShell's execution policy validation process.

---

- Validate whether malicious activity occurred.

## Investigation

The investigation identified that PowerShell generated a temporary file named:

```
__PSScriptPolicyTest_XXXXXXXX.ps1
```

This file is automatically created by PowerShell to verify execution policies before running commands.

The file was created in:

```
AppData\Local\Temp
```

which is a directory frequently abused by malware.

Because of this location, Wazuh generated Rule 92213.

---

## Root Cause Analysis

Root Cause:

PowerShell automatically generated a temporary execution policy validation script.

The alert was triggered because:

- PowerShell created a file.
- The file was written inside the Temp directory.
- Sysmon Event ID 11 captured the file creation.
- Wazuh correlated the activity with Rule 92213.

No malicious payload was executed.

---

## False Positive Assessment

| Item | Result |
|------|--------|
| Malware Detected | No |
| Legitimate Process | Yes |
| Alert Valid | Yes |
| Malicious Activity | No |

This alert represents a legitimate detection rule that generated a false positive because PowerShell uses temporary scripts during normal execution.

---

## Security Impact

Risk Level:

Low

Although the alert severity is high, the investigation confirmed the activity originated from a trusted Microsoft PowerShell process.

No compromise of the endpoint was identified.

---

## Recommendations

- Verify the originating process before escalating.
- Correlate Sysmon Event ID 11 with process creation events.
- Review parent-child process relationships.
- Tune detection rules if this behavior is expected in the environment.
